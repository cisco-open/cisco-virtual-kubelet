  ⚠️  THE CRDs ARE NOT UPGRADED AUTOMATICALLY ON HELM UPGRADE.

  Helm only installs files under crds/ on FIRST install; subsequent upgrades
  leave existing CRDs in place. If this release adds new fields to existing
  CRDs (e.g. Wave-10 fields like spec.confirmTimeoutSeconds, spec.atomicReplace,
  status.commandCount on IOSXEDiagnostic) you will see "unknown field" errors
  on apply until you patch the CRDs manually:

    kubectl apply -f charts/cisco-virtual-kubelet/crds/

  This is one-time per upgrade and is safe — CRD updates are
  schema-additive across this branch.

  After helm upgrade, run kubectl apply -f charts/cisco-virtual-kubelet/crds/
  if upgrading from a version prior to 0.1.0.

  ───────────────────────────────────────────────────────────────────────────

  RBAC RECONCILE — the chart updates ClusterRole bindings on every helm upgrade,
  so the iosxediagnostics + configmaps verbs needed by the diagnostics
  reconciler (Phase B-D) propagate automatically. If you see the
  per-pod-kubelet log emit:

    "iosxediagnostics is forbidden: User <ServiceAccount> cannot list
     resource ..."

  it means the ClusterRoleBinding hasn't yet picked up the new role — restart
  the cisco-vk-system controller deployment to force a re-bind:

    kubectl rollout restart -n cisco-vk-system \
      deploy/cisco-vk-cisco-virtual-kubelet-controller

  ───────────────────────────────────────────────────────────────────────────
