    Image Distribution

    How to get a container image from a registry (Docker Hub, GHCR, a private registry) onto a Cisco device managed by CVK.

    The problem

    A pod's image: field is not a registry reference. CVK accepts:

    • a flash path such as flash:/virtual-kubelet/my-app.tar, or
    • an HTTP(S) URL that serves a Docker-save tar.

    A value such as nginx:latest does not work. IOS-XE app hosting installs a Docker-save tar, so something has to turn the registry image into a tar the device can fetch.

    Options

    Option How Use when
    Pre-stage on flash Copy the tar to the device yourself, then image: flash:/... with imagePullPolicy: Never Air-gapped devices, or one image deployed to a few devices
    Any HTTP server Host Docker-save tars on a web server and use the URL as image: You already build and publish tars
    docker-http-passthrough An HTTP service that builds the tar on the fly from any registry V2 API (no Docker daemon) You want to deploy images straight from Docker Hub, GHCR, or a private registry

    The rest of this page covers the third option. The first two need nothing beyond Image delivery.

    How it fits

    ---
config:
  layout: dagre
  theme: default
  look: classic
---
flowchart LR
    Pod["Pod<br/>image: http://passthrough:8080/docker/nginx_latest.tar"] --> VK["CVK virtual kubelet"]
    VK -->|"install RPC or copy RPC"| Dev["Cisco device"]
    Dev -->|"HTTP GET .tar"| PT["docker-http-passthrough"]
    PT -->|"registry V2 API"| Reg["Registry<br/>Docker Hub, GHCR, private"]

    The device downloads the image. Either the device pulls the URL natively, or, if that times out, the VK's copy RPC makes the device download it to flash. The passthrough must therefore be reachable from the device. It does not need to be reachable from the VK or from other cluster pods, and the VK never fetches the tar itself.

    Run the passthrough

    Follow the project README for running it with Docker, Docker Compose, or the kubernetes.yaml manifest. This page does not repeat those instructions.

    • Image: ghcr.io/cisco-open/docker-http-passthrough (linux/amd64 and linux/arm64)
    • Listens on port 8080; health check at /health

    Pod examples

    Docker Hub image through the passthrough's default registry:

    spec:
  containers:
  - name: web
    image: http://passthrough.example.net:8080/docker/nginx_latest.tar
    imagePullPolicy: IfNotPresent

    GHCR image, with the registry named in the URL (my-org/my-app:1.2):

        image: http://passthrough.example.net:8080/registry/https/ghcr.io/docker/my-org__my-app_1.2.tar

    Filename rules (full list in the passthrough README):

    • The name must end in .tar.
    • The last _ separates the image path from the tag.
    • __ stands for / in the repository path.
    • Tags that contain _ cannot be represented.

    Credentials

    Where credentials live Works with CVK?
    Passthrough environment (REGISTRY_USERNAME, REGISTRY_PASSWORD, and so on) Recommended. Pod URLs carry no secrets.
    CVK spec.imagePullSecrets Applies to the copy path only, as basic auth on the copy RPC URL. See imagePullSecrets.
    Passthrough client-auth routes (/registry-auth/..., REGISTRY_CLIENT_AUTH) with Cisco ip http client username/password Device-side credentials. Combining them with imagePullSecrets is not qualified.

    Configure registry credentials on the passthrough and keep pod URLs credential-free. The passthrough README documents the environment variables.

    imagePullPolicy and timeouts

    • imagePullPolicy: Never rejects HTTP URLs. Use IfNotPresent (default) or Always.
    • The passthrough prepares all layers before it sends the first byte. A large image can therefore exceed the device-native pull wait (default 3 minutes) and trigger the copy fallback. Raise the wait with the cisco.io/apphost-package-timeout annotation; see Pod annotations for the copy path.
    • When the native pull succeeds, no tar is kept on flash, so IfNotPresent re-downloads on every deploy. See Image delivery.

    Limitations and security

    • The payload is the linux/amd64 image. Confirm that matches your device platform.
    • The passthrough needs temporary disk space for the layers of each request.
    • The examples use plain HTTP. Place the passthrough on a trusted network or front it with TLS.
    • It fetches from whichever registry host the URL names. Do not expose the /registry/... routes openly.
    • It holds registry credentials when you configure them in its environment. Protect it accordingly.

    Validation status

    Validated with CVK on a Catalyst 9000.

    The passthrough project publishes its own validation table for Cisco app hosting.

    Troubleshooting

    • Pod stuck in PullingImage
    • IfNotPresent still re-downloads
    • Never with an HTTP image URL
    • Kubernetes pod events emitted during image delivery
