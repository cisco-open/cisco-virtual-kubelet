# Credential cleanup: worker completion and manager finalization

Branch `pr/johalley/catc-support`; pinned NetAsCode module **0.5.0**.
This stage supports completion publication and manager release for an already-held
credential discovery finalizer. Automatic enrollment and public worker deletion
orchestration remain unavailable; full model parity is not claimed.

## Shared completion construct

Live cleanup and completion now share pure retained-evidence validation. Closed
work requires complete creator/retirement pairs, exclusive inventory ownership,
no outstanding journal operation or owned cancellation, valid generation/name
bounds and retirement of every latest owned incarnation. Missing or orphaned
history cannot become an empty successful cleanup. Empty/unowned and mixed
ordinary/credential histories are not enabled here.

The worker brackets two complete native absence reads with unchanged config,
controller and history checks. Closed work needs no replacement source or local
projected bytes. It emits the existing completion envelope with an optional
versioned `CredentialDigest` covering selected owners, action receipts and every
delivered-version application. Existing ordinary JSON remains unchanged because
the new field is omitted when empty. The global evidence digest also binds the
complete configuration state, including unrelated retained work.

Both completion families share fresh config checks, ownership-retirement
publication and status-only completion publication. Worker metadata privilege,
transport, finalizer names, CRD fields and receipt stores remain unchanged. The
existing retirement record retains the credential applications in its selected
digest. Ordinary ownership handoff refuses the typed record rather than dropping
or adopting credential history.

## Independent manager validation

The existing manager callback independently reconstructs both canonical records
from the current deleting config, controller identity/generation, owner and full
retained evidence. It performs no source, file, Secret or controller API reads.
A credential completion condition alone cannot release the finalizer: the
matching controller retirement record must also exist. Changed config, owner,
pairs, receipts, generation or either record fails validation.

The real manager reconcile is exercised after worker publication. It removes
only the discovery finalizer, preserves the unrelated keeper, retains the whole
owned audit and makes zero native requests. New enrollment eligibility is not
expanded by this stage. This does not enable ordinary/credential ownership
handoff or an unqualified end-to-end public lifecycle.

## Qualification

Eleven lifecycle modes cover inline/ConfigMap/active jobs, missing/changed source
and projections, deleted source ConfigMap, reappearing native work, pruned pairs,
pending journal work and lost/rejected completion writes. Twelve additional pure
manager alterations exercise owner, pair, receipt, both records, controller/config
identity, cleanup-family conflict, pause, deletion state and unexpected source or
digest fields. Workers are wrapped with status-only permissions during proof
publication. Both controlled persistence and real local Kubernetes API tests run.

The API fixture now registers Deployment/RBAC types read by manager bootstrap.
Controller protection is established before the worker binds its generation,
matching normal startup; production generation checks were not relaxed. Ordinary
API deletion is included explicitly, and the final expanded suite includes all
discovery API cases, including ownership handoff compatibility.

## Remaining boundaries

Automatic credential enrollment and worker deletion orchestration, pre-deletion
in-flight drain, empty/unowned and mixed histories, credential ownership handoff,
proven no-dispatch recovery, installed actors and native credential-bearing
cleanup remain pending. Native lab checks are read-only. Device CLI/SNMP
credentials remain unavailable for actual credential-bearing discovery
qualification. The 93-resource ledger remains explicit and full pinned parity is
incomplete. Adjacent JSON records exact source digests and gate results.
