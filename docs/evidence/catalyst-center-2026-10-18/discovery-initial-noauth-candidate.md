# Initial NoAuth discovery lifecycle

The exact qualified implementation and public manifest are now **applied** to the
branch; actual-worktree targeted checks passed with 503 events. This does not qualify native
discovery creation. The full overlay regression passed with 2,738 events after
the native bulk wireless run restored its baseline. The [qualification record](discovery-initial-noauth-candidate.json)
binds each gate to its own source; an earlier passing gate does not qualify a later
candidate revision.

The candidate enrolls a new SNMPv3 NoAuthNoPriv discovery owner through the existing
manager finalizer, typed source attestation, v4 input, one-use dispatcher, native
readback, action journal and deletion lifecycle. Metadata creates no credential
delivery record. Initial ordinary/typed history adoption remains refused. Initial
NoAuth enrollment currently requires the manager-enrolled Delete lifecycle.

Sixteen lifecycle cases passed on controlled storage and again against an isolated
real Kubernetes API. They cover inline/ConfigMap creation and cleanup, original
Unknown task recovery, Prepared cancellation, missing source or source attestation,
foreign native names, and source loss after durable cancellation proof. Additional
cases complete public handoff from metadata-only or cancelled owners to a projected
owner at version 1, deliver the first projected credential under the same owner,
and return to metadata while preserving its recorded delivery. A metadata-only or
never-submitted predecessor invents no delivered version floor.

discovery no-dispatch predicate recognised v3 only. Four cancellation cases passed;
the fifth retained its fence with zero appliance mutation attempts. The candidate
now admits recognised v3/v4 scope formats through the existing strict operation

contamination and stale ownership keep their fences. The corrected candidate passed
**423 regression events**, including thirteen new metadata refusal cases per
persistence backend. The superseded full run was deliberately stopped for this fix;
it is not counted as a passing gate.

All **five live read-only cases then passed** with real Catalyst Center reads and an
isolated real Kubernetes API: inline and ConfigMap cancellation, lost retirement

preserved the one-job/three-device baseline with zero native mutation attempts.
