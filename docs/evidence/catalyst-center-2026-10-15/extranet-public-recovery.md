# Extranet public preparation, recovery and settlement

## Current bounded lifecycle

Fabric-only Apply now routes explicit-scope extranet policies through the existing
group runtime (`controller-configuration-group-v1`). Public reconciliation
validates every declared policy and requires metadata prerequisites to converge
before choosing one pending action. It claims section ownership, repeats native
and managed planning, and prepares the existing shared physical group. Unknown
source sections, unowned later expansions and unresolved later dependencies do
not produce a partial operation.

The shared manager/worker reservation path supplies all-member grants, maintenance
authority and claims. Prepared restart dispatch reuses the previously tested
one-shot extranet bridge. It does not accept a callback in place of the shared
submission permit or bypass persisted actor authority. The first public-cycle
fixture correctly remained Prepared until the existing deployment/worker/session
authority fixture was supplied; production checks were unchanged.

Acknowledged Accepted or Unknown-with-task operations resume through the common
group verification transition. The adapter verifies the complete task tree,
resolved source, old creation ownership for updates, repeated native policy/VN/
fabric inventory and immutable CiscoDevice/Node targets. It compares full policy
baselines between observations and repeats the tree after readback. A failed or
running child, missing task, changed source/owner, replaced member or denied actor
retains the outstanding operation and claims without replay.

Verifying publication repeats native/managed/task evidence, then invokes the
existing atomic action-receipt writer. A targeted test demonstrated that a child
failure arising during publication authorization could previously escape the
earlier check. The public wrapper now rechecks the tree inside authorization,
before the atomic writer can publish Verified. Both create and update refusal
tests pass. The pre-fix broad run was stopped and is not final validation evidence.

The original creation receipt remains the native UUID ownership proof. Additive
updates retain baseline-bound v2 operation identities and publish their separate
action receipt. Existing native v1 receipt verification is preserved; legacy v1
unfinished journals remain fenced rather than gaining a new submission path.

Terminal completion/release/manager settlement reuse the existing retained-state
route, including recovery after source deletion. The adapter does not fabricate
worker release or manager settlement. Once every member settles, the journal
retires while receipts remain. Subsequent matching-source reconciles reach InSync
without claiming another permit or repeating POST/PUT.

## Verification and limits

The corrected focused recovery/public tests passed in 21.777s. They cover create
and owned additive update, including complete inline and ConfigMap cycles from
public preparation through dispatch, task verification, atomic receipt,
completion, partial settlement and final repeated InSync readback.

Other cases cover running/failed/late-failing child tasks, Unknown-with-task,
missing task/member, replaced Node/worker, source/owner changes, denied or
incomplete publication, lost publication acknowledgement, changing policy UUID,
publication-time child failure and zero native replay. The existing terminal
fixture verifies lost completion acknowledgement and withheld journal retirement
until worker release and manager settlement are present.

Whole-source public preflight tests refuse invalid later scopes, unowned later
updates, missing metadata prerequisites, unknown extra sections and absent group
runtime without appliance writes. The ordinary-runtime complete/pruned journal
fence tests remain intact. Runtime manager/connector/protocol/RBAC checks passed
on the final revision in 4.052s. Full affected race and documentation results are
in the companion logs.

These tests use actual shared reservation/candidate/claim/lease/permit/receipt
implementations with simulated Kubernetes, worker/manager evidence and native
HTTP actors. They do not qualify an installed cluster or live forwarding. No new
transport, journal schema, receipt collection or alternative coordination system
was introduced. ND and direct-device upgrades retain their existing paths.

Current native read-only prerequisite queries all return HTTP 200: no fabric-site
rows, two L3 VN rows and no extranet-policy rows. No isolated fabric was selected,
and no native policy or device mutation was submitted by this qualification.
