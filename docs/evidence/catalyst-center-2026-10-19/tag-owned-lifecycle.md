# Durable tag creator and latest-state evidence

The public inventory/templates tag path now reuses the existing configuration journal, ownership exclusion, source snapshot guards and `ActionApplications` atomic status writer to retain immutable creator evidence and a separately replaceable latest-state row. No new CRD, transport, state machine, credential store or native submission permit is introduced.

A versioned internal operation binds the tag name digest, desired payload digest and inline/ConfigMap source mode. Create verification requires the original completed Grouping Service task's canonical UUID and matching native desired-state readback. The receipt includes the original owner, controller/source revisions, operation/task and native UUID. An owned Update retains the creator unchanged and replaces only that tag's latest-state row after UUID-bound native readback. Fingerprints cover all currently observed writable tag attributes; unknown native fields are not claimed as a complete native baseline.

The writer checks source/owner/controller state, unchanged retained evidence and capacity before dispatch and publication. The executor refuses replaced/protected tags and writable-state drift from its settled receipt, reserves room for all missing selected creators and their future latest-state rows, and does not adopt imported tags. The common release path refuses Verified operations whose exact receipt is missing, duplicated or changed. One-use pre-submit refusals reuse the existing proof path; attempted or ambiguous native outcomes remain fenced.

Native qualification against Catalyst Center plus isolated real Kubernetes persistence passed Create and Update recovery from the original Unknown tasks. Exactly one POST and one PUT were permitted. The original creator stayed immutable and the latest-state row matched the current manifest generation and native UUID/attributes. Supervised cleanup checked the original Create task UUID and empty consumers, then restored the complete tag catalog baseline. This is not manifest-driven deletion or an installed-actor qualification.

The initial composition gate found fixtures that counted/indexed the entire shared receipt slice as discovery-only. That failed run is preserved. The corrected fixture validates the independent tag creator, checks its immutability through discovery transitions, and applies every original discovery assertion to the remaining discovery evidence. The corrected mixed-discovery gate passed. The final affected race gate passed 755 events in 40.047 seconds, including controlled and real-API inline/ConfigMap sources, tag recovery, receipt integrity/settlement/capacity, pre-submit refusal proofs, examples and mixed discovery transitions. A fake ConfigMap setup error in an earlier run was corrected by leaving resourceVersion unset on Create; its failure evidence is retained separately.

The existing shared receipt count/byte limits bound scale; planning reserves room for the complete missing selection and future latest-state rows before its first effect. Pruning/deletion, recreation lineage, broader native reference coverage, dynamic-rule ownership qualification and installed actors remain open. This is not full tag or pinned-model parity.
