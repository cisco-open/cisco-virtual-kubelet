# Owned tag source pruning

Later work adds [predecessor-bound recreation](tag-recreation.md). This file preserves the source-pruning qualification stage and its original limits.

Public inventory-only, templates-only and combined metadata tag manifests now support `prunePolicy: Delete`. Removing a tag from that same config UID requests UUID-bound cleanup through the existing journal, native task recovery and atomic ActionApplications receipts. Explicit empty lists and omitted/default-empty tag sections follow the pinned module's name-keyed union and empty-selection semantics. Inventory still overrides template definitions of the same name.

Start with `examples/configs/catalyst-center/tags-owned-prune-apply.yaml`, then apply `examples/configs/catalyst-center/tags-owned-prune-empty-apply.yaml` to the same object. Both keep CR deletion at Retain. The examples are compiled without sending native requests.

Cleanup requires the original creator, same owner/section/native UUID, unchanged complete native detail state and absent known consumers. Prune-enrolled Creates and owned Updates retain a complete native detail fingerprint alongside the writable-state fingerprint in the same receipt. Unknown attributes are preserved in that complete fingerprint. Earlier writable-only receipts cannot authorize deletion; a genuine explicit owned Update can retain the stronger latest-state baseline without rewriting the creator.

The preflight queries the [advertised resource types](https://developer.cisco.com/docs/catalyst-center/get-tag-resource-types/) and independently includes template associations. It requires zero [member counts](https://developer.cisco.com/docs/catalyst-center/get-tag-member-count/) before and after complete paginated membership reads for networkdevice, interface and template. Unknown/duplicate/missing type metadata, unreadable/contradictory counts or lists, state drift, replacement, protection and unexpected disappearance all refuse cleanup. The complete selected cleanup cohort is checked before its first effect and again before one-use dispatch. The API does not offer an atomic external-writer lock; these checks establish the observed pre-submit boundary.

An acknowledged Delete resumes only its original task. Verification requires authoritative task completion and repeated full-catalog absence of both original UUID and name digest. An immutable absence tombstone is persisted atomically with Verified, and the common release path requires that exact receipt. Taskless/lost acknowledgements, reused creation/update task IDs, and mismatched receipts stay fenced. Capacity is reserved through the existing shared count/byte limits. No CRD, transport, state machine, credential store or submission permit was added.

Native qualification passed three public manifest cycles with isolated real Kubernetes persistence: a new complete-state creator, and an older Retain creator followed by an explicit Update supplying the stronger baseline. A final inventory-only cycle also passed against the final runtime after the asynchronous proof correction. Each recovered its original tasks, sent exactly one POST/PUT/DELETE, retained immutable creator plus latest-state plus tombstone evidence and restored the entire prior tag catalog through manifest-driven cleanup. The controlled/real-API matrix covers all three scopes, explicit/omitted empty selections, older baselines, each consumer class, unknown types, full-state drift, foreign/protected/missing native objects, incomplete/contradictory observations, late-consumer refusal, all-member preflight, reused tasks and lost acknowledgements.

The earlier failed gates and the fixes they required are retained in the machine-readable evidence. In particular, the stricter refusal test exposed the old inventory synchronous-only proof assumption; the final narrow exception supports only validated asynchronous tag operations and preserves other inventory families.

CR-driven deletion, recreation after a tombstone, cross-owner handoff, owned dynamic-rule native lifecycle, ConfigMap prune execution qualification and installed actors remain open. Shared receipt limits also bound cardinality. This is bounded source-prune support, not complete tag or 93-resource parity.
