## Qualified result boundary

A captured original native Create task identifies service `Site Profile Service`
and uses the exact grammar `Network Profile [UUID] Successfully Created`. The
private decoder first applies the existing task ID, submission-time, terminal
and failure checks, then requires that service, exact prefix/suffix and one
canonical nonzero lowercase UUID. It does not search generic prose, accept
embedded JSON, trim text, or infer an identity from arbitrary UUID fields.
Raw progress is never retained or returned.

The private read-only verifier joins that task-returned UUID to the exact compiled
switching name and namespace, original project/template binding, desired native
template membership and complete rooted task tree. It repeats the original task
result and selected native observations; changed UUIDs, original dependencies or
private inherited state refuse verification. Numeric precision and semantic
attribute ordering use the same existing in-memory comparison as dispatch.
No native mutation, status write or operation mutation occurs in this verifier.

This is a prerequisite for creator custody. It is not yet connected to atomic
creator-receipt publication in the public reconciler. Existing ordinary Retain
completion and generic recovery contracts are unchanged. Future publication must
bind original owner/source/operation, preflight receipt capacity before mutation,
require a versioned receipt before journal release, reject imports/replacements,
and preserve legacy task semantics. Successful correlation alone grants no
adoption, pruning or deletion authority.

## Verification

Grammar fixtures reject wrong service/task/action, whitespace or appended text,
uppercase/nil/braced/duplicate UUIDs, JSON/object progress, missing timing/error
fields, stale/future evidence and failed/pending tasks. Read-only native fixtures
cover missing/replaced/renamed/wrong-namespace targets, membership/dependency
changes, failed/pending/unavailable trees, changed repeated task results,
replacement between reads, inherited numeric changes and semantic reordering,
and unsupported taskless/physical/credential/Update envelopes. Input operations
remain unchanged and mutation counts stay zero.

The focused race gate passes 108 test events, including existing switching
submission guards and public task/preflight recovery. A separate native cycle
creates an isolated profile with a real generated template/project dependency.
Its exact original Create result UUID, complete tree, dependency lineage and
stable selected native state pass this verifier. Three definition tasks recover
from Unknown through the existing public journal, with automatic preflight
replanning and restarted no-ops. The empty-area assignment and generated profile,
area, template and project are all cleaned up. Native Kubernetes persistence is
simulated; this new private verifier adds no status persistence path.
The production worker and strict documentation builds pass. These are focused
prerequisite gates, not a new full-model/installed regression claim.

Qualification outcomes, task identifiers, fingerprints and log hashes are in
[the machine-readable evidence](switching-profile-create-result.json).
