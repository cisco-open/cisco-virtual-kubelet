# Tag recreation with complete predecessor lineage

A newer manifest revision can reintroduce a previously pruned tag under the same config UID and journal section. The new Create binds the original deletion operation and a canonical digest of the complete predecessor cohort: immutable creator, optional latest-state row and absence tombstone. The existing shared cohort digest and input ordering helpers are reused. This adds resource semantics to the one configuration journal, with no new CRD, transport, store, state machine or submission permit.

The executor requires absence of the old UUID, desired name and retired UUIDs before dispatch. The original acknowledged Create task must identify a fresh native UUID matching native readback. Publication archives the entire old cohort and adds the new creator in one status CAS. Archive validation reconstructs each cohort, checks its receipts and digest, walks owner/section/source/time-bound predecessor links, and requires every retained cohort to be reachable. Missing, tampered, duplicated, orphaned or cyclic lineage stays fenced. Creator/latest-state/tombstone release checks require this ancestry, so matching current metadata cannot replace lost history or adopt a foreign tag.

Controlled and real-Kubernetes API qualification covers inventory, templates and combined scopes; one/two recreate-update-prune cycles; original-task recovery; foreign/resurrected objects; reused UUIDs; and missing/tampered cohorts. Separate ConfigMap source cases qualify prune, two recreation cycles, late-consumer proof and reused-task refusal on both backends. Their source UID/resourceVersion changes supply the new input epoch without requiring config-generation changes. These source-form cases use the controlled native API backend and do not claim installed or native ConfigMap end-to-end execution.

The live Catalyst Center qualification completed an initial create/update/prune plus two recreate/update/prune cycles with isolated real Kubernetes persistence. It recovered all nine original tasks and sent exactly three POSTs, three PUTs and three DELETEs. Three distinct UUIDs, two complete archived cohorts and the current final tombstone were verified; all fixture state was removed by manifests and the complete prior tag catalog was restored. Private per-phase checkpoints were retained during the run; selected nonsensitive status checkpoints are copied alongside the evidence.

Use the existing declared-tag and empty-selection examples on the same object, waiting for InSync at the current observed generation after each update. Reapplying the declared-tag example after verified pruning starts a fresh owned lifecycle. It does not adopt a recreated object already present outside CVK. Older writable-only baselines retain their prior pruning limits and need an explicit owned Update before cleanup.

The earlier synthetic-fixture failure and corrected gate are preserved. The final affected gate is recorded separately from the native and broader compatibility source snapshots. CR-driven deletion, owner/section handoff, owned dynamic-rule native lifecycle, native ConfigMap/installed qualification and shared scale limits remain open. Recreation support does not complete tag or full pinned-model parity.
