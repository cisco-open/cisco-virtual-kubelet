# Public acknowledged PnP removal recovery and content refusal

The public reconciler now selects retained PnP cleanup before edited/empty
inventory can fall through to an unrelated executor. Verifying acknowledgements
are recovered through the existing source/owner/journal bracket and independent
absence receipt. Verified operations release only with intact proof. Prepared
work is not dispatched, and Unknown/Submitting work stays fenced. No new public
Delete dispatch is enabled; the public status remains Waiting/Ready=False rather
than advertising whole-model convergence.

The cleanup-only reader now refuses attached day-zero configuration, previews,
credentials and headers, as well as known project/workflow/image/profile/tag and
claim-parameter references. Empty supported defaults are accepted; unknown keys
or shapes in these protected subtrees are refused. Only a refusal bit survives
safe paging. No secret/configuration value, preview, header or low-entropy secret
hash is retained. The bit cannot be cleared by a conflicting native false flag.
Ordinary PnP dependency snapshots remain unchanged.

Clean rows omit the new bit, preserving prior clean native fingerprints. Attached
content changes the private snapshot and fails eligibility; it does not acquire
cleanup authority from an older weak baseline. This is bounded protection of the
listed fields, not a claim that all possible future native consumer classes have
been discovered.
