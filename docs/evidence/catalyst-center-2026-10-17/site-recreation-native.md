# Native area retirement and recreation

The generated-area component lifecycle passed against the Catalyst Center lab:
public private-key Create, staged source omission and guarded retirement, source
reintroduction and guarded recreation, then a second guarded retirement returning
the typed site inventory to its exact starting baseline. No device assignments,
workloads or physical operations were changed.

## Native proof

The [race-enabled live test](site-recreation-native.log) passed in **30.74 s**
(**32.838 s** Go duration). There were exactly **two Create POSTs and two Delete
requests**. A test-only transport allowlist bound POST bodies to one generated
area and its Global parent, and Delete requests to verified creator UUIDs. Each
mutation allowance was consumed before the native request, including on error.
Unknown outcomes would retain their existing operation; no speculative cleanup
or replay was installed.

The first creator had a verified native task/result UUID. Both retirement tasks
were retained as acknowledged Unknown and recovered through their original native
task trees, repeated absence/ancestry observations and atomic retirement receipts.
The recreation task was also recovered as acknowledged Unknown with no writer
returned. Its new native UUID, exact desired attributes and complete task tree
preceded the production atomic predecessor archive/successor publication.

Final status has **four action rows**: two unchanged original producer operations
under archive keys, plus the current creator and final retirement. All four native
tasks are distinct, section ownership remains, and no active operation remains.
The [validation audit](site-recreation-native-validation.json) records task IDs,
counts, exact source hashes and the private recovery checkpoint location.

## Persistence and qualification boundary

The native requests use CVK's existing authenticated transport and resource
executors. The existing live manifest harness simulates Kubernetes persistence
and worker restart; this is not an installed controller run or API admission
qualification. Its new checkpoint wrapper saves config/controller state privately
after source and status updates. A generated test-only comparison projection is
retained there with directory mode 700/file mode 600 so a failed run would not
lose its key or exact task/source frame. Neither API credentials nor installed
Kubernetes Secret values are copied into evidence.

The [compile-only check](site-recreation-native-compile.log) deliberately skipped
native execution without the explicit opt-in; it is not counted as live proof.
The subsequent enabled run above is the native proof. Existing local and temporary
API gates are recorded separately in [staged execution evidence](site-recreation-execution.md).

## Remaining gaps

Public manifest/compiler routing, complete operational/settings consumer
protection, parent/child retirement coordination, configuration deletion and
installed complete-cycle qualification remain open. This run qualifies an empty
area only; building/floor and archived-ancestor lifecycles require additional
native evidence. The installed worker image was not replaced. Full site lifecycle
and all 93 pinned resources remain incomplete.
