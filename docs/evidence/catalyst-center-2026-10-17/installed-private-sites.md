# Installed private site Create/Update and retained state

The [real installed qualification](installed-private-sites-native.log) passed in
**76.85 s** (Go command **78.928 s**). The existing Kubernetes 1.35 qualification
cluster ran the normal Helm manager and isolated Catalyst Center worker image;
the host test only changed intent, observed public journal state and independently
verified native results through the existing Catalyst Center client. No fake
client, in-process reconciler, substituted worker credential path or exported
comparison key participated in execution.

## Verified lifecycle

The generated area/building hierarchy was independently absent before Apply.
The existing worker projection supplied its approved private comparison key.
The installed worker then created both resources and published two private
creator receipts. A source-only latitude change issued the building Update,
preserved both original creator rows and published one private latest-applied
receipt. The observer independently verified all three original task trees and
the exact desired native attributes.

Replacing the actual worker Pod preserved all three receipt rows and reached
InSync with a newer controller-check timestamp. This is settled-state restart
and no-op evidence, not proof of interruption during an accepted operation.
Unchanged journal/native state was observed; no wire proxy counted HTTP requests.

Deleting the configuration with Retain removed the intent object while leaving
one owner and all three private action rows in the controller journal. It did
not retire custody or grant another configuration adoption authority. After
confirmed intent removal and no outstanding operation, supervised cleanup used
the exact creator UUIDs in child-before-parent order, rechecked native identities,
remaining children and existing device/PnP consumer gates, and observed both
acknowledged cleanup tasks and resource absence. The complete typed site
inventory returned to its baseline. Public manifest-driven site Delete is not
attested by this independent cleanup.

[Task identities, source fingerprint and qualification boundaries](installed-private-sites-validation.json)
separate the three installed tasks from the two supervised cleanup tasks.
Physical operations, device adoption, provisioning and SWIM were not submitted.

## Build recovery and subsequent qualification

The [first command](installed-private-sites-build-failed.log) failed during
linking because the host disk was full; no test or Apply ran. Removing only older
generated entries from the task's Go build cache recovered approximately 20 GiB;
[cache recovery metadata](installed-private-sites-build-cache-recovery.json)
records that no source or evidence file was removed. The successful command was
started only after the earlier build process was confirmed terminal.

The initial read-only/private-key probe remains a separate, correctly refused
input combination: the report contract permits no secret references. The
installed Apply result uses the existing private-site Apply contract unchanged.

The completed connector was subsequently retired through its normal public
protection finalizer. It retained its worker while the completed read-only
report still referenced it; removing that report let normal quiescence finish.
No finalizer was bypassed, and retained ownership evidence was saved before
connector deletion. A fresh isolated connector and new generated hierarchy now
support the separate accepted-task process-restart qualification. That result
must be recorded independently; a prepared or running command is not a pass.

## Accepted-task process recovery: terminal result

The [separate accepted-task command](installed-private-sites-accepted-native.log)
also passed: **71.99 s** (Go **74.412 s**). It uses the same normal worker and
private hierarchy flow with an explicit test-only interruption gate. The observer
first checks exact cluster/controller UIDs and the dedicated context. It obtains
the sole worker's runtime container identity from its Pod status, requires the
exact private kind node and container name, and stops only that container using
the node's runtime. No extra permission or interruption hook was added to CVK.

After the process stopped, the Kubernetes journal still contained the original
acknowledged Update task and only the two creator rows. Kubelet restarted the
same Pod with a different container identity and increased restart count. The
real new worker recovered that exact original task, verified its full tree and
native/private state, and published the latest-applied receipt. It did not
replace the task with a new acknowledgement. The later settled Pod replacement,
Retain intent deletion, exact supervised cleanup and baseline restoration also
passed. [Task/source audit](installed-private-sites-accepted-validation.json)
records the original task identity and separates the three installed tasks from
the two cleanup tasks.

This establishes real installed recovery of the accepted building Update;
other action/uncertainty combinations are not inferred. Five
[identity/interruption refusal gates](installed-private-sites-safety-gates.json)
also reject missing kubeconfig, wrong context, wrong cluster/controller UIDs and
unknown interruption modes before native access. Default-off
[compile/skip evidence](installed-private-sites-accepted-disabled-gate.log) is
separate from the native pass.

Private-key rotation/migration, floor/AP and physical actors, ownership
handoff/retirement, public site prune/Delete and the remaining pinned-model
resource gaps are still open.
