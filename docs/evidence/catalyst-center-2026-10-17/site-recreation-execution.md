# Staged site retirement and recreation execution

A retired site can now be bound to its later reintroduced declaration through
the existing singular site executor. The recreation selector binds the exact
predecessor retirement and creator/latest cohort, config owner, source frame,
comparison-key scope, site kind/path hash and original surviving parent identity.
The worker resolves the existing projected comparison key; it does not read a
Secret through the Kubernetes API or introduce another transport/client.

## Execution and recovery

Planning requires repeated native absence at the declared path, absence of old
lifecycle UUIDs anywhere in inventory, no children at the absent path, and the
surviving ancestry authenticated by the retirement receipt. The existing native
site planner creates the payload. Singular dispatch repeats exact typed and full
native ancestry/payload checks around the existing source/owner/journal guard.
Current full receipt history and archive capacity are rechecked at submission.
Images and planned AP effects are refused until their lifecycle coordination is
implemented; they are not silently omitted from an admitted model.

An exact unsubmitted Prepared operation can reconstruct its writer. Accepted,
acknowledged Unknown and Verifying operations reconstruct an observation executor
only, with no writer returned. They retain the original task and use complete
native task-tree verification. Taskless uncertainty cannot reconstruct a writer.
Original-task result UUID and repeated native desired-state verification precede
publication through the production atomic archive/creator status CAS. Section
ownership and original producer operations/timestamps survive settlement.

No public policy/compiler route is opened by this change. This is the staged
execution boundary used to complete and qualify that future lifecycle.

## Qualification scope

The tests first submit and verify a staged native Delete through the existing
retirement path, then change the declared source and invoke recreation. Native
HTTP and task responses are controlled fixtures. They exercise the real resource
planner, transport mutation method, one-use writer, common journal, source/key
checks, original-task observation and production creator publisher. Temporary
Kubernetes API cases additionally use actual source generations/resourceVersions,
status CAS and current CRD schemas. They do not prove native Catalyst Center
retirement/recreation or installed controller routing.

The matrix covers inline/ConfigMap source reintroduction, creator-only and
creator/latest predecessor cohorts, occupied paths, moved old UUIDs, replaced
ancestry, late source/key/history changes, Accepted/acknowledged Unknown,
pending/failed tasks, lost acknowledgement, HTTP 401/500 uncertainty and Prepared
resumption. The [final race regression](site-recreation-execution-regression.log) passes
**62 families / 861 subcases** in **80.594 s**.
The [temporary Kubernetes API gate](site-recreation-execution-api.log) passes
**7 families / 97 scenarios** in **68.283 s**.
The new staged execution cases account for 32 local cases and eight API cases.
The [validation audit](site-recreation-execution-validation.json) records the
exact source boundary and explicit remaining gaps.

## Remaining gaps

Public policy/compiler routing, complete operational/settings consumer ownership,
parent/child retirement coordination and configuration deletion remain pending.
Building/floor retirement/recreation, archived-ancestor cycles and native installed
complete-cycle qualification still need explicit evidence. The installed lab
worker has not been updated for this staged path, and no new native lab mutation
is claimed. Full site lifecycle and all 93 pinned resources remain incomplete.
