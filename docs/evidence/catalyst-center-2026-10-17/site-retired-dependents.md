# Retired descendant coordination

Staged parent retirement now distinguishes retained child custody from a live
native dependency. Complete verified descendant lifecycles can remain in status
while the parent is retired. Their original creator, optional latest update and
retirement rows are not deleted or rewritten. Other retained image/AP/credential
and cross-section effects remain blocking.

## Authority and native checks

The bounded retained graph is traversed across current and archived cohorts.
Each reachable cohort is reconstructed with the existing creator/latest/
retirement validators, preserving owner and comparison-key scope. Every edge
requires a supported child kind, exact native parent UUID, an earlier completed
child retirement and compatible config/controller generations. Parent and child
operation/task identities cannot be borrowed across an edge. Unknown or partial
cohorts, unretired descendants and retained descendant credentials/effects refuse
authority. Only exact receipt fingerprints are excluded from the retained-effect
fence; a path or a matching name alone grants no permission.

Planning, guarded dispatch and original-task recovery retain all descendant UUIDs
and path hashes as absence requirements. A retired descendant reappearing at a
new location, or a replacement at its old path, blocks parent retirement.
Source declarations that reintroduce these descendants also block the operation.
The existing whole-history snapshot, native dependency reader, source/key checks,
one-use writer and status CAS remain in place. No new transport or journal was
introduced, and no public Delete policy/compiler gate was opened.

## Qualification

Controlled fixtures exercise complete retired child/grandchild graphs, archived
lifecycles, missing producers/retirements, owner/key/generation/task/time drift,
retained effects/credentials and native UUID/path reappearance. Integration cases
continue through guarded parent Delete, original-task observation, atomic receipt
publication and settlement with child history preserved. Temporary Kubernetes API
cases use the current CRD schema and actual status/source persistence. Fixture
child proofs are synthetic and are not ownership adoption evidence.

The [final race regression](site-retired-dependents-regression.log) passes
**63 families / 893 subcases** in **83.017 s**.
The [temporary Kubernetes API gate](site-retired-dependents-api.log) passes
**7 families / 102 scenarios** in **69.74 s**.
The new cases comprise 22 structural dependency scenarios and 10 inline/ConfigMap
parent execution cases; five of the latter also run against the temporary API.

The [native parent/child run](site-retired-dependents-native.log) passed in
**29.71 s**. It created a generated parent and child,
retired the child, then retired the parent while retaining both creator and
retirement receipts. Original acknowledged Unknown tasks were recovered without
replay. There were exactly two Create POSTs and two Deletes, four distinct tasks,
four retained rows, unchanged section ownership and a terminal idle journal.
The typed site inventory returned to its exact starting baseline.

A separate [native recreation regression](site-retired-dependents-native-recreation.log)
passed in **30.39 s** against the same source boundary.
Create/retire/recreate/retire again used exactly two POSTs/two Deletes and four
original tasks, retaining its archived predecessor and restoring its starting
baseline. No device assignment, workload or physical operation was changed.

The [validation audit](site-retired-dependents-validation.json) records exact
hashes, native task IDs and private recovery checkpoint locations. Generated
comparison projections and full checkpoints stay private; credentials and keys
are not copied to evidence. Native qualification uses simulated Kubernetes
persistence/restarts and does not qualify installed/public retirement routing.

## Remaining integration

Parent/child retirement is only one direction of lifecycle coordination. A child
recreated after its parent receives a new UUID needs an explicit authenticated
parent handoff; the existing same-parent recreation fence is retained. Public
routing, complete operational/settings consumer ownership, configuration deletion,
building/floor native cycles, native parent retirement after archived child
recreation, and installed complete-cycle qualification remain
pending. Full site lifecycle and pinned 93-resource parity remain incomplete.


## Subsequent parent handoff

A separate [parent handoff implementation](site-parent-handoff.md) now adds an
explicit replacement-parent proof to child recreation. Its qualification boundary
supersedes that remaining item only; public/installed routing and broader native
coverage remain open. Historical gates and hashes above are unchanged.
