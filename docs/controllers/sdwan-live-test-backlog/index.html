    This is a progress inventory, not a claim of completed deployment parity. The pinned NetAsCode v1.5.0 module contains 226 resource declarations. Current status:

    Live tests required for implemented definitions

    For each row, run native create/read/update/read/idempotence and receipt-bound cleanup, followed by Kubernetes reconciliation with the selected fixture. Include dependency creation order, missing-reference behavior and resolved IDs for reference-bearing parcels. Do not attach these fixtures to routers as part of object qualification.

    All 32 policy-object child declarations passed native create/read/update/delete under the existing Manager policy-object profile using isolated CVK names. The original parent child-ID set was verified after cleanup for each fixture. The singleton profile itself remains unqualified: CVK does not adopt or update the existing lab profile, so its creation still needs an empty test Manager.

    Native test commands

    Provide Manager credentials through the existing environment/secret mechanism. The transport example below has passed; use the table above to select remaining fixtures. Select one fixture at a time, starting with absent fixture names.

    CVK_SDWAN_LIVE=1 CVK_SDWAN_MUTATE=1 \
CVK_SDWAN_PENDING_FIXTURE=transport-trackers \
go test ./internal/controlleradapter/sdwan -run "^TestLivePendingLifecycle$" -count=1 -v

# On a Manager with one existing policy-object profile, child fixtures can
# be tested without creating or updating that parent. Run one fixture at a time.
CVK_SDWAN_LIVE=1 CVK_SDWAN_MUTATE=1 \
CVK_SDWAN_POLICY_FIXTURE=policy-security \
go test ./internal/controlleradapter/sdwan -run "^TestLiveExistingPolicyObjectChildren$" -count=1 -v

# On a lab whose vSmart meets the prerequisites above, select one activation
# fixture at a time. The test verifies an empty baseline and registers cleanup
# before sending the deployment request.
CVK_SDWAN_LIVE=1 CVK_SDWAN_MUTATE=1 \
CVK_SDWAN_ACTIVATION_FIXTURE=topology-group-activation \
go test ./internal/controlleradapter/sdwan -run "^TestLiveActivationLifecycle$" -count=1 -v

# KUBEBUILDER_ASSETS points to the Kubernetes 1.35.0 envtest binaries.
CVK_SDWAN_LIVE=1 CVK_SDWAN_ENVTEST_LIVE=1 \
CVK_SDWAN_ENVTEST_FIXTURE=transport-trackers.yaml \
go test -tags envtest ./internal/controlleradapter/sdwan -run TestEnvtest -count=1 -v

    For the existing policy-profile.yaml fixture use TestLivePolicyProfileLifecycle. All examples have report-mode companion NetworkControllerConfig manifests.

    Compatibility-blocked

    sdwan_other_trustsec_feature: Manager 20.18 requires sxpNodeId, absent from the pinned provider model; its empty device-password default is also rejected. The compiler rejects this fixture before mutation. Fixing the compatibility mapping and passing live tests are both still required.

    Broader deployment validation

    Device attachment, policy/topology activation, operational routing/forwarding, asynchronous recovery, pruning and import remain implementation and qualification work. The optional TestLiveActivationLifecycle has baseline checks and a restoration cleanup registered before activation; its current lab attempts failed at the prerequisites recorded above. Object CRUD tests do not qualify these workflows.
